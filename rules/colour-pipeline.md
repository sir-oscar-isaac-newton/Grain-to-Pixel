# Colour pipeline invariants

- Process internally in 32-bit float, linear light; keep 16-bit integer only at file I/O boundaries.
- Order: ingest → frame crop → film-base measure/normalize → invert → noise reduction → colour balance → colour mixer → tone → split toning → geometry → vignette. The colour mixer works in Oklch (hue, saturation, lightness per hue band), changes only colourful pixels (a gate fades every change to nothing towards grey), and its band weights add up to 1 at every hue; it does nothing in black and white, and the pickers and the automatic balance measure the frame before the colour stage, so they never see it. Noise reduction works in Oklab: the lightness by undecimated wavelet shrinkage (a trous, B3 spline, five scales, a soft threshold per scale from the noise level measured on the picture itself, the finest scale reduced least so fine grain stays, `NR_WAVELET_STRENGTH` 0.9 and shares 0.3, 0.8, 1, 1, 1 chosen by the owner and to be tuned in Q-11, about 0.86 s for the whole stage at 24 MP on 6 threads; ADR 0020), then the two colour planes by a guided filter guided by the cleaned lightness (ADR 0013); it runs on the positive straight after the inversion, so it never sees a colour edit, it is not part of the frames the pickers measure, the colour radius and strength and the scales of the wavelet follow the size of the image relative to the full scan (1 at export), and its tiles, patches and box averages are summed in a fixed order, so the result is identical on any number of threads. Split toning blends towards a tint of the same luma, so it changes colour and never brightness. The vignette comes after geometry so it is centred on the final picture, and it is a gain on all three channels, so it never shifts hue. Dust removal (IR) runs on the scan data before inversion.
- The IR plane is never treated as a colour channel; it is carried alongside RGB.
- Edits are non-destructive: store parameters as a `Recipe` in a sidecar/catalog, never overwrite the source scan.
- Film-base measurement is stored per roll and overridable per frame. The first frame analyzed on a roll with no base stores its measurement, with the confidence, as the roll's base (`ensure_roll_base`); a stored base, by hand or automatic, is never overwritten by a later frame. An automatic base below confidence 0.5 is kept but flagged for a manual pick.
- The film base is measured with medians, never means (dust and hot pixels must not move it): from a user-chosen rebate area (a click or a dragged box), or automatically from the brightest of four thin border strips, with a confidence that is low when no clear rebate exists. The roll base is the per-channel median over its frames. Normalization is `T = I / base` with the base floored at 1e-6, so the result is always finite.
- Inversion is linear in density: `P = max(0, (D - black) / (white - black))` with `D = -log10(T)`. It does not apply the film's contrast curve; that belongs to the tone stage and is calibrated against reference renders. Auto black/white come from density percentiles (0.5 and 99.5) of the cropped frame only, never the rebate.
- A frame of a black-and-white roll is inverted from one combined density: `invert.combine` holds the channel weights (inverse-variance, from the frame's own noise; equal when the noise cannot be measured), `D = sum(w_c * D_c) / sum(w_c)`, one black and one white point (the means of the recipe's three), and `P` is written to all three channels, so the picture is grey from here on. It skips the colour stage and the colour mixer (they would only tint it); noise reduction, tone, split toning, geometry and the vignette still run. Which inversion a frame uses follows its roll's film type: a saved recipe that disagrees is refitted when it is loaded to be developed, shown as a thumbnail or exported, and the per-channel points of the old recipe are dropped, never carried over (ADR 0017). A colour roll's inversion and output are untouched.
- Frame detection runs on the base-normalized scan and classifies rebate as luminance within 0.06 of 1.0; it never trusts a brightness step. Below 0.5 confidence it returns the full frame, so a wrong guess is never silent.
- Colour gains always multiply to 1 (brightness is kept); tone controls act on luma and scale the pixel, so they never shift hue; only curves and colour controls change colour. Every edit constant is a named `pub const` in `gtp-edit`, to be tuned in Q-03, never a literal in the maths.
- Geometry resamples at most once: angle 0 is an exact pixel copy, any other angle is one bicubic sample per output pixel at the composed transform; the straightened frame is the largest same-aspect rectangle inside the rotated crop, so no corner is ever invented.
- `render` uses the recipe exactly as given; automatic values only ever come from `analyze` and are written into a recipe. Crop runs before normalize (as an exact copy) and geometry after tone, so there is one resample at most. Parallel stages must give results identical to a single thread (no cross-row sums inside a stage).
- Embed an ICC profile on every export; state the working space in the Recipe. Export converts linear Rec.2020 with Little CMS, relative colorimetric intent (white stays white; D65 to D50 for ProPhoto by Bradford), bringing colours above 1 into range first by the hue-keeping rule `gtp_core::bring_into_range` (ADR 0019; the same on the screen and in every export, grey included), after which Little CMS still clips per channel what lies in range but outside a narrower output space. Exported colours are checked against independent maths in `tools/benchmark/tests/export_colour.rs` (ΔE2000 below 1). An untoned black-and-white frame (`invert.combine` set, both split-tone strengths 0, and red, green and blue curves that are all the identity or all the same) is exported as one grey channel instead, through Little CMS to a grey profile with the D65 white and the sRGB tone curve, whatever the output space; toned frames, frames with a tinting channel curve and colour frames stay RGB, and the `colour` export option can force RGB (ADR 0018).
